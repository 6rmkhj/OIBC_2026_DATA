# Read-only progress viewer

The viewer reads local campaign JSON receipts and verifies PID, process group, start ticks, and boot ID. It never trains, resumes, stops, or changes a model. `server.py` optionally serves the monitor on `127.0.0.1:8765`; only `/` and `/api/status` are exposed.

The original `research_10h_20261107` campaign remains visible while the continuation supervisor waits. Once the new controller starts, the viewer switches to `research_22h_20261107` and retains that stage after it finishes. It distinguishes crossfit generation, residual calibration, completion, and report generation, and displays the supervisor's verified liveness and checkpoint status. Counts of actual model fits use `real_model_fits`; reused predictions and deterministic median corrections contribute zero. Candidate ratios use the original c000 five-period baseline; corrected/raw-base ratios are labeled separately. These internal results are not a newly queried official score or an independent holdout.

For file previews in Codex, run `python write_snapshot.py --interval 10` (or `--once` for one save). It reads the latest `template.html` on every write, atomically generates `index.html`, and updates the original campaign's `LIVE_STATUS.md` every ten seconds. File previews may require reopening to show a newer saved snapshot. The HTML displays its saved timestamp and does not poll an API when opened as a static preview. Edit the versioned template, not generated `index.html`.

`template.html` and the Python generators are versioned. Generated `index.html`, `LIVE_STATUS.md`, launch identities, and logs stay local. The snapshot writer freezes its stopping time at startup to two minutes after the authorized deadline and saves its final observation. Restart the viewer and writer after an authorized extension or source update. The overall deadline is displayed separately from each controller's unchanged stage deadline; the original campaign's immutable configuration is never altered.
