# OIBC 2026 제출 후보 검증 결과

검증일: 2026년 11월 2일. 제공 데이터 README를 기준으로 기존 파이프라인을 점검하고, 구성 선택 기간을 분리한 제출 후보를 새로 학습했다. 제출 후보는 참조 구성보다 가중 오차가 2.77% 작았고 기존 제출의 예측 수준을 유지했다. 실제 테스트 정답과 리더보드가 없으므로 수상권 여부는 아직 판단할 수 없다.

## 제출할 산출물

`submission/award_candidate/`의 **composition.csv와 forecast.csv를 한 쌍으로 사용**한다. 기존 `submission/composition.csv`와 새 예측 파일을 섞으면 구성과 예측 대상이 달라진다. `submission_files.zip`에는 이 두 CSV만 들어 있으며, 공식 제출 화면이 개별 파일을 요구하면 압축을 풀어 각각 올린다. 이번 작업에서는 대회 서버에 제출하지 않았다.

| 검사 | 결과 |
|---|---:|
| 발전소 | 253개, 중복·누락 없음 |
| G1 용량 | 21,208.195 kW |
| G2 용량 | 21,447.175 kW |
| 예측 데이터 행 | 17,520행, 헤더 별도 |
| 집합별 시각 | 공급 SMP와 동일한 8,760개 |
| 예측 기간 | 2025-06-01 01:00 ~ 2026-06-01 00:00 KST |
| NaN·무한대·음수 | 없음 |
| 연간 예측 발전량 | 60.6139 GWh |
| 자기 집합 용량을 넘는 예측 | 없음 |

형식 검사는 별도의 표준 라이브러리 기반 코드로 수행했다. 중복 발전소, 잘못된 그룹, 용량 부족, 중복·잘못된·시간대 없는 시각, 음수, 무한대, NaN의 9가지 잘못된 입력도 거부했다. 결과: [candidate_checks.json](../award_run/candidate_checks.json).

## 성능을 어떻게 검증했나

구성 선택과 성능 평가를 시간순으로 분리했다. 미래 실측 기상이나 테스트 정답은 사용하지 않았다.

| 단계 | 범위와 용도 |
|---|---|
| 초기 학습 | 2021-01-19 13:00 ~ 2023-06-01 00:00 |
| 구성·비중 선택 | 2023-06-01 01:00 ~ 2024-06-01 00:00 |
| 후기 평가용 재학습 | 2024-06-01 00:00까지 |
| 후기 평가 | 2024-06-01 01:00 ~ 2025-06-01 00:00 |
| 제출용 재학습 | 제공된 모든 학습 실적, 2025-06-01 00:00까지 |

초기 선택에서는 참조 구성과 오차 상관 기반 쌍둥이 분할 각각에 직접 모델 비중 0%, 25%, 50%, 75%, 100%를 적용했다. 10개 조합 중 **쌍둥이 분할·직접 모델 50%**가 선택됐다. 개별 발전소 예측은 pooled LightGBM L1 5시드 평균 90%와 발전소별 L2 10%를 섞는다. 선택 설정과 배정은 후기 평가를 시작하기 전에 저장했으며, 후기 결과에 따라 다시 선택하지 않았다.

초기 선택 오차는 후보 13.2102%, 참조 구성 50% 블렌드 13.4126%였다. [선택 결과](../award_run/inner_selection.csv), [고정 설정](../award_run/locked_configuration.json), [날짜 경계](../award_run/boundaries.json).

## 후기 평가 결과

여기서 W%는 `100 × Σ(SMP × k × 집합별 절대오차) / Σ(SMP × k × 실적)`인 **내부 비교 지표**다. 공식 순위 점수의 백분율이 아니다. 낮을수록 좋다.

| 모델·구성 | 후기 1년 W% | 해석 |
|---|---:|---|
| 참조 구성 + 동일 50% 블렌드 | 11.8816% | 비교 기준 |
| 새 제출 후보 | **11.5526%** | 이전 기간에서 설정 고정 |
| 기존 제출 구성의 새 코드 재현 | 11.5493% | 구성 선택에 후기 실적을 사용한 진단값 |

새 후보는 참조 대비 0.3290%p, 가중 오차 총액으로 2.7691% 개선됐다. 공식식 `S = Σ SMP·실적 − 0.10 × W`에 대입한 후기 기간 점수 차이는 약 **568.6만 원 상당**이다. 이는 과거 검증 구간의 환산값이며, 미래 수익이나 테스트 기간 이득을 보장하지 않는다.

기존 저장값 11.5515%와 수정 코드로 재현한 11.5493%는 다른 실행 결과다. 새 후보 11.5526%는 기존 제출을 능가했다고 말할 수준이 아니다. 이번 결과의 핵심은 비슷한 예측 수준을 유지하면서 구성 선택의 평가 기간 재사용을 줄이고 실행을 재현 가능하게 만든 점이다.

일별 블록 2,000회 재표본추출에서 후보−참조의 W% 차이 95% 구간은 **−0.4482 ~ −0.2165%p**였다. 동일 검증 연도 내 일별 불확실성을 나타내며, 연도 간 기상 변화나 모델 선택 전체의 불확실성까지 포함하지 않는다. 날짜 블록은 KST 달력일 기준이며 마지막 자정의 부분 블록을 포함해 366개다. [bootstrap.json](../award_run/bootstrap.json).

## 전체 발전소와 취약 시기

후기 실적은 2,170,645개 발전소·시각 행이며 완전한 253개소 격자는 2,216,280행이다. 발전소 편입 전 결측을 실적 0으로 채우지 않았고 해당 실적이 존재하는 행끼리 비교했다. 2024년 6월의 관측 커버리지는 약 84.15%, 2025년 1~5월은 100%다.

| 구간 | 후보 W% | 참조 W% |
|---|---:|---:|
| 전체 발전소 실적이 있는 2025년 1~5월 | 10.2235% | 10.3667% |
| 높은 가중치가 적용되는 ts 11~15시 | 11.2382% | 11.5748% |

전체 발전소 구간은 `2025-01-01 00:00 < ts <= 2025-06-01 00:00`으로 다시 계산했다. 3,624시간 × 2집합, 7,248행이다. 후보는 2025년 4월과 5월에는 참조보다 소폭 나빴다. 2024년 7월·9월 후보 오차는 각각 약 16.61%, 16.55%로 높았다. 따라서 모든 계절에서 우수하다는 주장은 피해야 한다. 원 월별 표는 ts 달력월 기준이라 `2025-06`은 마지막 자정 한 시각만 포함한다.

초기 선택 연도에는 48개 발전소의 실적이 없었다. 이들의 상관 계산용 오차 열은 0으로 채워졌으므로 해당 발전소의 쌍 배정에는 충분한 실적 근거가 없다. 이 사실은 [고정 설정](../award_run/locked_configuration.json)의 `unseen_inner_sites`에 기록했다.

기존 모델 구조·피처·일부 가중치는 과거 분석에서 후기 연도를 보고 정해졌다. 따라서 이번 결과도 완전히 미사용인 최종 홀드아웃은 아니다. 최종 일반화 성능은 대회 테스트 점수로 확인해야 한다.

## 발견한 문제와 반영한 수정

1. **구성을 고른 기간에서 다시 평가:** 기존 11.5515%는 개발 점수로 명시했다. 새 실행에서는 초기 선택과 후기 평가를 분리했다.
2. **정상 예보까지 덮어쓰기:** 일부 변수만 누락된 행에서 17시 예보 전체를 10시 값으로 교체했다. 누락된 셀만 보완하도록 수정했고, 정상 운량 1이 9로 바뀌던 재현 사례가 이제 1을 유지함을 확인했다.
3. **파일 존재 여부만 보는 캐시:** 기존 실행 경로는 이 동작을 유지하되 한계를 안내했다. 권장 실행 경로는 원자료·코드·설정·패키지 버전 지문과 실제 캐시 내용 해시를 검사한다. 기존 CSV는 보존했다.
4. **검증 종료일 누락:** 명시된 종료일 T2를 검증 마스크에 반영했다.
5. **용량 비교:** 기존 검사에서 전체 집합 중 큰 용량을 비교하던 부분을 각 예측의 소속 집합 용량과 비교하도록 수정했다. 독립 제출 검사는 제공 README의 공식 조건과 물리적 참고 검사를 구분한다.
6. **잘못된 첫 제출 고정 안내:** 제공 README는 평가 연도 내 동일 배정을 요구한다. 첫 제출 후 변경 불가라는 기존 README 문구는 삭제했다. 제출 간 변경·횟수·동점·무효 세부 조건은 공식 문제정의서 확인 대상이다.

## 재실행과 검증 근거

프로젝트 최상위 폴더에서 실행한다.

```bash
python submission/validate_pipeline.py
python submission/validate_artifacts.py submission/award_candidate --self-check
python submission/verify_run.py
python submission/check_pipeline.py
```

이번 전체 실행은 약 443초 걸렸다. Python 3.12.10, numpy 2.5.4, pandas 3.1.0, pyarrow 26.0.0, lightgbm 4.7.0, scikit-learn 1.9.1, joblib 1.6.0을 사용했다. 다른 환경에서는 [provenance.json](../award_run/provenance.json)의 버전을 맞춘다. 캐시나 실행 중간에 문제가 생기면 오류를 숨기지 않고 중단하며, 불완전한 캐시를 자동 신뢰하지 않는다.

- [독립 점수·해시 재검증](../award_run/independent_verification.json): 학습 코드와 별도로 `math.fsum`을 사용해 W·수익·S를 재계산했고 기록값과 일치했다. CSV 실적은 기록된 float32 정밀도로 복원했다. 구성별 합산 순서로 생기는 총 실적 차이는 최대 0.001953125 kWh였다.
- [실제 실행 로그](../award_run/run.log), [실행 완료 기록](../award_run/verification.json), [원자료 및 코드 지문](../award_run/provenance.json).
- [수치·결측 보완 검사](../award_run/pipeline_checks.log): 두 집합 오차를 상쇄한 뒤 절댓값을 취하지 않는지 손계산으로 확인했다.
- [검토 결과](../../.omo/evidence/oibc-chronological-validation-code-review.md): 코드 품질 CLEAR, 차단 문제 없음. 이후 생성된 최종 후보는 별도 독립 형식 검사를 통과했다.

새 Python 파일과 수정 파일의 컴파일 및 실행 검사를 통과했다. LSP 서버는 설치되어 있지 않고 이전 설치 거절 상태여서 사용하지 않았다. 폴더는 Git 저장소가 아니므로 커밋은 생성하지 않았다.

## 수상 도전에 적용할 판단

이번 후보는 제출 형식과 재현 근거가 갖춰진 기준 제출로 사용할 수 있다. 첫 공식 결과를 확보하면 같은 평가 체계에서 다음 실험의 가치를 판단할 수 있다. 특히 현재 개선 여지는 구성보다 예측 오차가 큰 흐린 시기·여름철과 최근 대형 발전소의 상태 변화에 있다. 다음 실험을 한다면 새로운 미사용 검증 구간이나 시간순 외부 폴드를 확보한 뒤 비교해야 한다.

현재 폴더에는 공식 문제정의서와 채점 코드가 없다. 제출 세부 조건과 외부 모델·데이터 허용 범위는 최신 공식 공지를 확인해야 한다. 테스트 정답·실제 리더보드·상대 참가자 성능을 확인하지 않았으므로 수상 확률이나 예상 순위는 산정하지 않았다.
