# verify_genq_math — 발전량 이상치·정제규칙 주장에 대한 적대적 검증 (math/logic 렌즈)

검증 대상 주장: "플래그된 발전 이상(음수, CF>1, 야간 비영, 플랫라인, 주간 결측)은 실제이며, 제안된 정제 규칙(야간 강제 0, 음수→0, CF>1→1)은 정상 데이터를 제거하지 않는다."
스크립트: `verify_genq_math.py` (cf_wide + sites.csv + smp_all만 사용, 원본 parquet 미사용). 로그: `out/vq_verify_genq_math_log.txt`.

## 판정: **부분 반박 (refuted=true, 신뢰도 0.7)**

* 이상치 **개수·규모는 모두 재현됨** (음수 40건 −3.85 kWh 10개소, CF>1 9건/8개소 최대 1.034, 내부 결측 7시간 PV051 1건, 야간 비영 143,882h 중 박명 121,887h / 진짜 야간 21,995h, 진짜 야간 에너지 3,777 kWh = 0.0040%, VAL 결측 45,635/주간 27,774). 데이터 시각 규약(ts = 구간 끝)도 독립 검정으로 확인.
* 그러나 두 가지가 틀렸다.
  1. **"야간 강제 0" 규칙이 정상 데이터를 제거한다.** 보고서와 모델 코드(`model_validation.py` 75행 `df.elev > 0`, 패널 캐시 elev = 구간 중점)가 쓰는 야간 정의 "중점 고도 ≤ 0°"에는 **박명 발전 93,632 kWh(전체의 0.099%)** 가 들어 있고 그중 93,384 kWh는 구간 시작 또는 끝에 해가 떠 있는 시간이다. 보고서 스스로 "야간 비영의 85%는 박명의 기하학적 효과"라고 인정하면서 같은 정의로 0 강제를 권고한 것은 내부 모순. VAL 연도 기준 이 규칙의 **페널티 하한 W = 7.17e6(최우수 단일모델 W 2.115e9의 0.34%)**, 진짜 야간(≤−6°)만 0으로 하면 2.4e5(0.01%).
  2. **플랫라인 수치가 3배 과소(483h→1,539h, CF>5% 367h→1,165h)이고 해석("정오 포화 우연 일치")이 틀림.** 보고서는 런 길이 L에서 (L−3)만 합산했다(1,165 − 3×266런 = 367 정확히 일치). 플랫값은 해당 발전소 최대 CF의 **중앙값 10.3%**(p25 6.6%, p75 17.3%) 수준이고 90% 이상인 런은 0.4%뿐 → 정오 포화가 아니라 저출력 구간의 반복(정지된 계측값)이다. 다만 전체 셀의 0.035%라 "무시" 결론 자체는 유지 가능.

## 4. 수정 제안

1. 야간 정의를 "중점 고도 ≤ 0°"에서 **"구간 시작·끝 고도 모두 ≤ 0°"(또는 중점 ≤ −6°)** 로 바꾸고, 박명 구간은 모델 예측(또는 최근 30일 동일 시각 중앙값)을 쓴다. 기대 효과: VAL W 약 6.9e6(0.33%) 회수.
2. gen_quality 보고서 §3.4 수치를 1,539h(CF>5% 1,165h, 266런)로 정정하고 "정오 포화 우연 일치" 문구를 "저출력 구간의 반복 계측값(stale), 전체 셀의 0.035%"로 바꿀 것.
3. §7.4 권고 문구 "야간 강제 0 … 외 정제 불필요"에 야간 정의를 명시할 것(현재 코드 기준으로는 0.1%의 정상 발전을 지운다).
4. 나머지(음수→0, CF>1→1 클리핑, 결측 보간 불필요)는 검증 통과 — 변경 불필요. 참고로 model_validation은 CF를 (0, 1.2)로 클리핑해 CF>1 9건을 그대로 두는데, 9건/4.4M이라 어느 쪽이든 무차이.
